# Launch Ledger

A running ledger of what real dogfood sessions hit, kept separate from the formal gate system in [release-readiness.md](release-readiness.md). Gates prove evidence exists; this ledger tracks the stories that must land, the flows that must be smooth, and the paper cuts observed along the way. Update it during every dogfood session — an entry here is cheaper than rediscovering the same wedge two weeks later. Engineering-only entries are labeled explicitly and never substitute for installed two-PC evidence.

Status legend: `open` / `in-progress` / `fixed (commit)` / `needs-evidence` (fix landed, real two-PC proof missing).

## Nits and paper cuts

- `daemon status` reported `daemon_version=5.0.0` on a 5.0.10 install. BND-NEXT-29 item 4 remains open until the installed v5.0.13 helper run proves the runtime version matches the package.
- `boundlessctl` output is single-line `key=value` prose; machine consumers (scripts) have to regex it. A `--json` flag would have prevented the c2e1509 bug class outright.
- `Boundless-Install.ps1` postcondition verification is code complete in 6cf425f/59ec987; the real helper/UAC upgrade still must prove it rejects stale or incomplete installation state.
- `Package.wxs` `MajorUpgrade` still lacks `AllowSameVersionUpgrades`, so dogfood rebuilds at the same semver silently no-op as upgrades. BND-NEXT-29 item 3 remains open; patch-version-per-artifact is the current workaround.
- WiX stale `obj`/`bin` cleanup is code complete in 6cf425f and covered by packaging-script smoke; keep it in the release gate.
- `input_lock_supported` reported `false` until the service was restarted after install — startup ordering between daemon and service-mode input leaves a degraded state that looks like a capability gap.
- Fresh-install service state observed `Stopped` with `StartType=Automatic` after an earlier session (2026-07-07 morning, likely fallout of the wedged install rather than a distinct bug — recheck after P0 #1).
- Smoke-zip hash in handoff notes was hand-transcribed and garbled (61 chars); handoffs should paste from `HANDOFF-SHA256SUMS.txt`, never retype.
- Two `boundlesstray` processes were observed after install/restart churn. The 5.0.12 ownership guard passed repeated Start launches; v5.0.13 lifecycle cleanup and stale-owner ordering are code complete (5172126, 81b1a4b, c5c52e1), but active-capture Quit/relaunch and upgrade process-count evidence remain pending under BND-NEXT-31.
- The released 5.0.12 MSI failed with error 1603 when launched without `BOUNDLESS_ALLOWED_USER_SID`. The documented helper entrypoint and post-install verification are code complete in 6cf425f/59ec987; both installed UAC paths remain pending under BND-NEXT-29.
- Clipboard-content removal and raw-output hardening are code complete in ebeebab/fcf53e7/474a8f7; BND-NEXT-37 remains `needs-evidence` until the installed sentinel sweep passes.
- Service-mode file receipt defaulted to the LocalSystem profile directory, which is not a usable desktop receive destination. BND-NEXT-36 requires an explicit user-visible folder for the one-file clipboard tracer bullet.
- Windows recorded four Application Hang 1002 events for the 5.0.12 tray since July 9. BND-NEXT-31 lifecycle cleanup and BND-NEXT-38 IPC-independent escape are implemented on the v5.0.13 candidate, but installed hang/fault reproduction and recovery are not yet proven.
