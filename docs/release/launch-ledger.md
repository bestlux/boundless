# Launch Ledger

A running ledger of what real dogfood sessions hit, kept separate from the formal gate system in [release-readiness.md](release-readiness.md). Gates prove evidence exists; this ledger tracks the stories that must land, the flows that must be smooth, and the paper cuts observed along the way. Update it during every dogfood session — an entry here is cheaper than rediscovering the same wedge two weeks later. Engineering-only entries are labeled explicitly and never substitute for installed two-PC evidence.

Status legend: `open` / `in-progress` / `fixed (commit)` / `needs-evidence` (fix landed, real two-PC proof missing).

## Nits and paper cuts

- Installed `boundlessctl --version` and `daemon status` both report 5.0.13; BND-NEXT-29 item 4 passed.
- `boundlessctl` output is single-line `key=value` prose; machine consumers (scripts) have to regex it. A `--json` flag would have prevented the c2e1509 bug class outright.
- `Boundless-Install.ps1` resolved the desktop user, requested UAC, and ultimately installed 5.0.13 on both PCs, but running-tray shutdown failed before postconditions could be first-try. BND-NEXT-41 owns the preflight; stale/incomplete rejection still needs a deliberate negative run.
- The v5.0.14 candidate adds `AllowSameVersionUpgrades="yes"` and packaging coverage for BND-NEXT-29 item 3; one installed same-version replacement remains the evidence gate.
- WiX stale `obj`/`bin` cleanup is code complete in 5dc1521 and covered by packaging-script smoke; keep it in the release gate.
- `input_lock_supported` reported `false` until the service was restarted after install — startup ordering between daemon and service-mode input leaves a degraded state that looks like a capability gap.
- Fresh-install service state observed `Stopped` with `StartType=Automatic` after an earlier session (2026-07-07 morning, likely fallout of the wedged install rather than a distinct bug — recheck after P0 #1).
- Smoke-zip hash in handoff notes was hand-transcribed and garbled (61 chars); handoffs should paste from `HANDOFF-SHA256SUMS.txt`, never retype.
- Three Start launches plus three direct v5.0.13 executable launches left one tray. v5.0.14 adds the true graceful Quit path shared by active-capture shutdown and helper quiescence; installed Quit/relaunch and upgrade process-count proof remains under BND-NEXT-31/BND-NEXT-41.
- The released 5.0.12 MSI failed with error 1603 when launched without `BOUNDLESS_ALLOWED_USER_SID`. Both PCs ultimately installed 5.0.13 through the documented helper/UAC path, but running-tray shutdown was not first-try and the deliberate stale/incomplete postcondition-negative case remains open under BND-NEXT-41/BND-NEXT-29.
- Clipboard-content removal and raw-output hardening are code complete in 42a31ad/6115c6b/b1f38a1; BND-NEXT-37 remains `needs-evidence` until the installed sentinel sweep passes.
- Service-mode file receipt defaulted to the LocalSystem profile directory, which is not a usable desktop receive destination. BND-NEXT-36 requires an explicit user-visible folder for the one-file clipboard tracer bullet.
- Installed v5.0.13 Double-Control still failed once with no `input_escape_triggered` event while PowerToys Find My Mouse recognized the same physical sequence. BND-NEXT-38 is reopened around detector reliability rather than IPC reconciliation alone.
- Installed v5.0.13 did not preserve numeric-keypad source semantics: `vkCode`/logical Num Lock meaning was lost for ambiguous digit/decimal scans, while scan/E0 remained intact. Track the v5.0.14 physical proof under BND-NEXT-40, not as a generic keyboard transport failure.
